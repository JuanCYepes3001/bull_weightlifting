### Cart Sync con Supabase Realtime

El carrito tardaba minutos en sincronizarse entre dispositivos. Se reemplazó el modelo polling por eventos Realtime:

| Problema | Solución |
|---|---|
| Sync tardaba minutos | Supabase Realtime en `cart_items` con filtro `cart_id=eq.{id}` |
| Loop infinito de sync | Ref `isSyncing` (bloquea reacción a propios eventos) + ref `skipNextSync` (bloquea echo al servidor) |

**Decisión técnica**: Dos refs separados en lugar de uno porque resuelven problemas distintos — `isSyncing` es local (este dispositivo) y `skipNextSync` es para el dispositivo receptor.

Archivos: `src/store/cartStore.ts` (+`replaceItems()`), `src/components/CartSyncProvider.tsx` (reescrito con 3 efectos)

Requiere SQL en Supabase (ya ejecutado):
```sql
ALTER PUBLICATION supabase_realtime ADD TABLE cart_items;
```

### Pagos — Implementación real

**PayPal (redirect flow, sin SDK):**
1. Cliente selecciona PayPal → `createPayPalOrderAction()` crea orden en API PayPal v2, guarda datos pendientes en cookie httpOnly
2. Redirige a URL de aprobación de PayPal
3. PayPal redirige a `/checkout/paypal-return?token=XXX`
4. `finalizePayPalOrderAction()` captura el pago, crea orden en DB, limpia cookie

Archivos nuevos: `src/lib/paypal.ts`, `src/app/(shop)/checkout/paypal-return/page.tsx`

**Variables requeridas (pendiente):** `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_MODE`, `COP_TO_USD_RATE`

**Nequi / Daviplata / Dollar App / Global 66 (verificación manual):**
- Orden creada con `payment_status: "pending_verification"`
- Success page muestra instrucciones paso a paso según `?method=` query param
- Cada método tiene sus propias instrucciones configurables via `NEXT_PUBLIC_*` env vars

**Estados de pago por método:**
- `simulado` → `approved`
- `contraentrega` → `cod_pending`
- Digitales manuales → `pending_verification`
- PayPal exitoso → `approved`

`checkout.ts` refactorizado con `insertOrder()` compartido entre flujo estándar y PayPal.

### Bug fixes

**TrusasCustomizer** — expandido de 3 campos a sistema completo:
- Nombre + Número (estampado)
- Diseño: Clásico / Bull / Minimalista (con descripción de cada uno)
- Color del estampado: 5 opciones con swatch
- Medidas personalizadas (toggle oculto): Pecho / Cadera / Largo en cm

`CartCustomization.color` renombrado a `printColor`. Nuevos campos: `design`, `chest`, `hip`, `torso`. `CartItemRow` actualizado.

**Botón contraseña** — root cause: `top-[14px]` falla cuando el `Input` muestra error (el contenedor crece y el cálculo se rompe). Fix: `top-0 h-11 flex items-center` — se ancla al alto exacto del input independientemente de lo que haya debajo. Aplicado en `LoginForm.tsx` y `RegisterForm.tsx`.

**Logo en auth** — `BullLogo` sin `withMark` solo muestra texto. Fix: `withMark` agregado al layout de auth → muestra imagen `bull-logo.png` (con fallback SVG).

**IP de red vs localhost** — NO es bug de código. Las cookies de sesión son por origen (comportamiento estándar del navegador). Al cambiar de `localhost` a la IP de red hay que hacer login de nuevo. Las credenciales son las mismas. Ver [[diario/pendiente-configuracion]] para configuración de Supabase Redirect URLs.
