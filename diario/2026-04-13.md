# 2026-04-13 — Sesión de polish frontend + scroll horizontal

Continuación desde [[diario/2026-04-12]]. Sesión enfocada en bugs de UI, reactividad del admin y el scroll horizontal de categorías en la homepage.

---

## Bugs corregidos

### Botón ver contraseña (raíz definitiva)
- **Síntoma**: el ícono Eye/EyeOff no hacía toggle al hacer clic.
- **Causa raíz 1**: El componente `Input` envuelve el `<input>` en `div.flex.flex-col.gap-1.5`. El botón absoluto con `top-0 h-11` dependía de que ese wrapper tuviese altura exacta de 44px, lo cual fallaba en Tailwind v4 por conflicto de especificidad entre `px-4` (base) y `pr-12` (override) — en v4 el orden de generación CSS puede hacer que `px-4` gane sobre `pr-12`.
- **Causa raíz 2**: El wrapper div del `Input` podría interceptar eventos de puntero antes del botón.
- **Fix**: Se reemplazó el uso del componente `Input` en los campos de contraseña por un `<input>` nativo directo con `pl-4 pr-12` explícito. El botón usa `inset-y-0 flex items-center` en lugar de `top-0 h-11`, lo que lo ancla verticalmente de forma robusta independientemente del contenedor.
- **Archivos**: `src/app/(auth)/login/LoginForm.tsx`, `src/app/(auth)/register/RegisterForm.tsx`

### Navbar tarda en aparecer al navegar
- **Causa**: `delay: 1.2` en la animación GSAP de entrada se ejecutaba en cada montaje del componente, incluyendo cada navegación entre páginas.
- **Fix**: Reducido a `delay: 0.1`, duración de `0.7s` a `0.5s`.
- **Archivo**: `src/components/layout/Navbar.tsx`

### Logo en auth muy pequeño
- `size="sm"` → `size="md"` en el `BullLogo` del auth layout. El mark pasó de 24px a 32px.
- **Archivo**: `src/app/(auth)/layout.tsx`

### Creación de categoría sin registro de actividad
- `createCategoryAction` no llamaba `logActivity`. También faltaba extraer `adminProfile` de `requireAdmin()`.
- **Fix**: Se agregó `const { profile: adminProfile } = await requireAdmin()` y `await logActivity(..., "category_created", name)`.
- El label `category_created` ya existía en `ACTION_LABELS` del dashboard — solo faltaba el llamado.
- **Archivo**: `src/app/actions/products.ts`

### Categoría nueva no se refleja en la tienda
- `createCategoryAction` sólo revalidaba rutas de admin. La tienda no se actualizaba.
- **Fix**: Agregados `revalidatePath("/")`, `revalidatePath("/categories")`, `revalidatePath("/products")`, `revalidatePath("/admin/dashboard")`.
- **Archivo**: `src/app/actions/products.ts`

## Decisión técnica compleja: Scroll horizontal de categorías

### Problema inicial
El scroll horizontal con GSAP `ScrollTrigger` + `pin: true` creaba un **spacer div** con altura = distancia total de scroll horizontal (miles de píxeles). Este spacer aparecía como espacio vacío entre la sección y lo que venía después. A medida que se scrolleaba (dentro del pin), el spacer se "consumía".

### Primer intento fallido
Se reemplazó con `overflow-x: auto` CSS + `scroll-snap-type: x mandatory`. El scroll snap funcionó para touch/drag pero el mouse wheel no producía scroll horizontal (el browser ignoraba el deltaY horizontal en el track).

### Diagnóstico definitivo (5 causas raíz)

| # | Causa | Síntoma |
|---|---|---|
| 1 | Listener en `sectionRef` (div exterior) | `preventDefault()` llegaba tarde — browser ya aplicó scroll nativo antes de que bubblee |
| 2 | `scroll-snap-type: x mandatory` | Peleaba con GSAP: snap reseteaba `scrollLeft` entre frames de la animación |
| 3 | `scrollSnapAlign: start` en cards | Consecuencia del #2, producia tug-of-war |
| 4 | `targetLeft` inicializado en `0` | Primer wheel event calculaba target incorrecto si el track ya estaba scrolleado |
| 5 | Cleanup removía listener del elemento equivocado | Leak de event listener al desmontar |

### Solución final
- **Wheel listener en el `trackRef`** (el elemento con `overflow-x: auto`), no en el div exterior.
- **`e.preventDefault()`** intercepta antes de que el browser aplique cualquier scroll nativo.
- **`gsap.to(track, { scrollLeft: targetLeft, ease: "power3.out", overwrite: true })`** anima suavemente.
- **Sin `scroll-snap-type`** — eliminado completamente para no pelear con GSAP.
- **`overflow-x: auto`** sigue presente para touch/swipe nativo en móvil.
- **Barra de progreso crimson** — actualizada por `onUpdate` en GSAP + listener `scroll` pasivo para touch.
- **Cursor grab/grabbing** — feedback visual de drag en desktop.
- Acumulación de `targetLeft` sincronizada con `track.scrollLeft` en bordes para no perder el estado.

```
Listener correcto: track.addEventListener("wheel", onWheel, { passive: false })
Animación: gsap.to(track, { scrollLeft: target, duration: 0.65, ease: "power3.out", overwrite: true })
```

**Archivo**: `src/components/home/CategoriesSection.tsx`

## Aclaración de no-bugs

### Cuentas localhost vs IP de red
Comportamiento del navegador, no bug de código. Las cookies de sesión de Supabase son por origen (`localhost:3000` ≠ `192.168.x.x:3000`). Las cuentas en Supabase son las mismas — solo hay que hacer login desde la URL con la que se acceda. No requiere cambio de código.

### TrusasCustomizer
El componente ya tiene nombre, número, diseño (Clásico/Bull/Minimalista), color de estampado (5 opciones) y medidas personalizadas (pecho/cadera/largo). Solo aparece en productos con `category.slug === "trusas"`. Verificar que los productos tengan esa categoría si no se ve el customizer.
