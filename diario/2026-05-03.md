## Qué hicimos

### 1. Carrusel de atletas en la sección BrandStatement

La sección motivacional (`BrandStatement.tsx`) fue completamente rediseñada como un carrusel de 5 slides que combina frases motivacionales con fotos de atletas del bucket `athletes` de Supabase.

**Arquitectura:**
- `BrandStatement.tsx` → server component: lista el bucket con `createAdminClient()` y pasa URLs al carousel
- `BrandStatementCarousel.tsx` → client component con GSAP: recibe `imageUrls[]` y maneja toda la lógica de animación

**Comportamiento:**
- Auto-avance cada 6 segundos
- Transición: fade-out del slide anterior → breve negro → fade-in del nuevo con texto en stagger
- Layout alternado: slides pares = texto izquierda / imagen derecha; slides impares = imagen izquierda / texto derecha
- Navegación: flechas prev/next + dots tipo línea (crimson cuando activo)
- Imagen como elemento en columna (no background), fondo `#111111` sólido
- `object-cover object-top` garantiza que todas las imágenes tienen la misma altura (`min-h-[62vh]`)
- Vignette lateral suaviza el borde entre imagen y texto

**Decisión clave:** usar `createAdminClient()` (service role) para el `storage.list()` del bucket — funciona independientemente de si el bucket es público o privado.

Ver concepto: [[conceptos/carrusel-gsap-react]] | [[conceptos/supabase-admin-client-rls]]

### 2. Script de importación de inventario

Se creó `scripts/import-inventory.mjs` (Node.js ESM con `exceljs`) para transformar el Excel de inventario en SQL listo para ejecutar en Supabase.

**Formato del Excel:**
```
ITEM | DESCRIPTION | QUANTITY | XS | S | M | L | XL | XXL | UNIT COST
```

**Primera versión (incorrecta):**
Cada fila del Excel → 1 producto separado. Resultado: 37 productos individuales donde cada color de camiseta era un producto distinto.

**Segunda versión (correcta):**
- Agrupa filas por `ITEM` → 1 producto por tipo de prenda
- `DESCRIPTION` = color → variante del producto
- Genera: categorías + productos + variantes (producto × color × talla) + imágenes por color
- SKU format: `{cat_code}_{product_code}_{color_code}_{talla}` → e.g., `01_01_01_M`

**Problema FK resuelto:** el primer SQL usaba UUID hardcodeado para `category_id`. Si la categoría ya existía en la BD con otro UUID, el `ON CONFLICT DO NOTHING` no actualizaba el id → violación de FK. Fix: usar `(SELECT id FROM categories WHERE slug = '...')` como subquery.

Ver concepto: [[conceptos/importacion-excel-supabase]] | [[conceptos/producto-variante-color-imagen]]

### 3. Migración 017 — color en product_images

Para soportar imágenes por color (swap al seleccionar variante), se añadió la columna `color` a `product_images`:

```sql
ALTER TABLE product_images ADD COLUMN IF NOT EXISTS color TEXT;
```

Esto permite consultar `WHERE product_id = $1 AND color = $2` para mostrar la imagen correcta según el color seleccionado.

## Decisiones tomadas

| Decisión | Razón |
|---|---|
| `createAdminClient()` para listar bucket athletes | El cliente anon puede fallar con buckets privados; el service role siempre funciona |
| Transición fade-out → negro → fade-in (no crossfade) | El crossfade causaba solapamiento visible de texto de ambos slides |
| `min-h-[62vh]` con `flex + py-14` para imagen | Garantiza que todas las imágenes tengan exactamente la misma altura en píxeles |
| Agrupación por ITEM en el import (no por fila) | Un producto = un tipo de prenda; el color es una variante, no un producto distinto |
| Subquery para `category_id` en lugar de UUID hardcodeado | Evita violación de FK cuando la categoría ya existe con diferente UUID en la BD |
| Columna `color` en `product_images` | Permite filtrar la imagen correcta por color sin lógica compleja en el frontend |
